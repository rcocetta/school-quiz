Make your own quizzes

A step-by-step guide for teachers and parents. You need a web browser, a free GitHub account and about ten minutes. You do not need to install anything or know how to program.

Words you will meet

GitHub
A free website where people keep and share projects. This project lives there.
Repository
A project’s folder on GitHub, with all its files. People also say “repo”.
Fork
Your own copy of a project. Changing your copy never changes the original.
Commit
Saving a change. GitHub asks you for a short note about what you changed.
Branch
A separate line of changes inside a repository. The main one is called main.
Pull request
A polite request to add your changes to someone else’s project.
Action
A little robot on GitHub. When you save a change, it checks your quizzes for mistakes and tells you with a green tick or a red cross.
Build
Turning your quiz files into web pages. A small program called quizgen does it, on a computer, and puts the result in the docs folder.
Pages
GitHub Pages: a free service that shows the files in a repository’s docs folder as a website anyone can visit.
JSON
The kind of text file a quiz is written in. It is just words in quotes, with a few commas and brackets.

1Make your own quiz site in 10 minutes

Do these steps once. Afterwards, adding a quiz takes a couple of minutes.

  1. Get a GitHub account.

    Go to github.com/signup and follow the steps. It is free. Your username becomes part of your website address, so choose one you are happy to share.

  2. Fork the project.

    Open github.com/rcocetta/school-quiz. In the top-right corner click Fork, then click Create fork. The name you give it becomes the last part of your website address, so keep it short, or leave it as it is.

    You are now looking at your own copy, at github.com/<your-username>/school-quiz.

  3. Turn on GitHub Pages.

    Under your repository name click Settings. If you cannot see it, open the … (More) menu and choose it there. In the left sidebar, under “Code, planning, and automation”, click Pages. Under “Build and deployment”, under “Source”, choose Deploy from a branch. Then, in the branch menu, choose main, and in the folder menu next to it choose /docs. Click Save.

  4. Wait, then visit your site.

    Click the Actions tab under your repository name. GitHub starts a run called “pages build and deployment” by itself. After a minute or two it shows a green tick. (GitHub says a change can take up to 10 minutes to appear.) Your site is now live at:

    https://<your-username>.github.io/<repository-name>/

    For example, user msrossi with a repository called school-quiz gets https://msrossi.github.io/school-quiz/. Your quizzes are on the quizzes/ page of that address.

    It works straight away because your fork already contains this project’s finished website in its docs folder. You will see the sample quizzes.

Good to know Your site starts with this project’s welcome page and this guide, and your quizzes are under quizzes/. If you would rather have your quizzes on the front page, see Turning off the project pages.
Editing is easy, publishing needs one more step You can write and fix quizzes in your browser, and GitHub checks them for you. But the website in docs is only updated when someone runs the build tool on a computer. Section 2 explains it. If that is not for you, ask a colleague, a family member or a developer, or open an issue and ask for help.
Careful Your fork starts with this project’s sample quizzes (Farm Animals and Times Tables, with their pictures) in the quizzes folder. Delete or replace them before you share your site, as described in the next section.

2Write your first quiz

A quiz is one text file whose name ends in .json. You create it right in your browser, with GitHub’s editor.

Create your quiz

  1. Open the quizzes folder in your fork. Click Add file, then Create new file.
  2. In the file name box type a name ending in .json, for example space-quiz.json. Use small letters and dashes, no spaces. This name becomes part of the quiz address.
  3. Copy the quiz below and paste it into the big text box.
  4. Click Commit changes… in the top-right corner. In the box that opens, write a short note such as “Add space quiz”, choose Commit directly to the main branch, and click Commit changes.
  5. Open the Actions tab. A new run of the checks appears. A green tick means your quiz is valid. A red cross means something needs fixing (see When something goes wrong). Your quiz is not on your website yet. That is the next part.

Publish it

Your website is built from your quizzes by a small program, quizgen, and the result is saved in the docs folder. GitHub does not do this step for you, so each time you add or change a quiz, someone has to:

  1. Install quizgen and download your fork to a computer. The README has step-by-step help: Installation.
  2. In a terminal, in your fork’s folder, run python scripts/build_docs.py. This rebuilds the docs folder.
  3. Commit and push the changed docs folder to main. A minute or two later your site shows the new quiz. If you still see the old page, wait a little and refresh.
Not a computer person? That is fine. Write the quiz yourself, then ask a colleague, a family member or a developer to do the three steps above, or open an issue and ask for help. A red “docs/ is out of date” cross on your fork only means the build has not been run since your last change.
space-quiz.json 
{
  "title": "Space Quiz",
  "description": "How much do you know about our solar system?",
  "questions": [
    {
      "text": "Which planet do we live on?",
      "explanation": "We live on Earth, the third planet from the Sun.",
      "options": [
        { "text": "Mars" },
        { "text": "Earth", "correct": true },
        { "text": "Venus" }
      ]
    },
    {
      "text": "What is at the centre of our solar system?",
      "options": [
        { "text": "The Moon" },
        { "text": "A comet" },
        { "text": "The Sun", "correct": true }
      ]
    },
    {
      "text": "How many planets are there in our solar system?",
      "explanation": "Mercury, Venus, Earth, Mars, Jupiter, Saturn, Uranus and Neptune.",
      "options": [
        { "text": "6" },
        { "text": "8", "correct": true },
        { "text": "12" }
      ]
    }
  ]
}

What the pieces mean

title
The name of the quiz. Required.
description
One friendly sentence under the title. Optional.
questions
The list of questions, between [ and ]. Each question sits in its own { }.
text
The words of the question, or of one answer.
options
The answers children choose from. Give two or more.
correct
Put "correct": true on the right answer. Every question needs exactly one.
explanation
A short note shown after the child answers. Optional, but children like it.
Tips for typing Words go inside double quotes. Put a comma between items, but not after the last one. The easiest way to add a question is to copy an existing one, paste it after a comma, and change the words.

Then tidy up the sample quizzes

  1. In your fork, click the quizzes folder, then click a sample quiz file such as farm-animals.json. (Do this after creating your own quiz.)
  2. In the top-right corner of the file, open the … menu and click Delete file. Write a short note such as “Remove sample quiz” and click Commit changes.
  3. Do the same for the other sample quiz. To remove the pictures, go back to the quizzes folder, open the … menu next to the folder name, and click Delete directory.
  4. Give your quiz page its own name: open quizzes/site.json, click the pencil (Edit this file), change the "title" and "description" text, and commit. Keep the file: it is what keeps the quizzes folder there.

Your own quiz stays. The Action starts again by itself when you commit, and your quiz list then shows only your quizzes.

One thing to know: a fork where you have deleted the samples is not a good starting point for sending a quiz to the shared library, because the request would delete them there too. Contributing back explains what to do.

If you make a typing mistake, nothing breaks: your old site stays online and the Action tells you what to fix. See When something goes wrong.

3Quiz file reference

Everything you can put in a quiz file, in plain words. Anything not listed here is an error, which helps catch typing mistakes. The README has the full technical table.

Fields of the quiz
FieldWhat it doesNeeded?
titleThe name of the quiz.Yes
questionsThe list of questions.Yes
descriptionA sentence under the title.No
questions_per_quizHow many questions each try asks, picked at random from your list. Leave it out and it asks 10, or all of them if you have fewer.No
feedback"immediate" (the default): the child taps an answer, presses Check my answer and sees at once. "end": nothing is marked until the end screen.No
shuffle_optionstrue (the default) mixes up the answers every time. Use false for answers in a fixed order, like 1, 2, 3.No
languageThe language of the buttons and messages. The default is "en". See Multiple languages.No
languagesTurns on several languages in one quiz. See Multiple languages.No

Fields of each question
FieldWhat it doesNeeded?

optionsThe answers: two or more, and exactly one marked "correct": true.Yes
explanationA note shown after answering, and in the review at the end.No
imageA picture for the question. See Adding images.No
image_altDescribes the picture for children who cannot see it.With image, please
Fields of each answer
FieldWhat it doesNeeded?
textThe words on the answer button.Text or image

image_altDescribes the picture. Needed when the answer is only a picture.With image, please

Tip: more questions than you ask Write 30 questions and set "questions_per_quiz": 10. Each try is a different mix, so children can play again without seeing the same quiz.

4Saying who made it

Add an author and the quiz says “Made by …” on its start screen and on its card in the quiz list. Put it near the top of your quiz file, next to title:

"author": { "name": "Class 4B", "url": "https://example.org/class-4b" },

name is required. url is a website address starting with https:// and turns the name into a link. email works too, but is only used when there is no url.

Keep it safe Quiz sites are public, so everything in them can be read by anyone.
  • Prefer a website address to an email address. Published emails attract spam.
  • If you do give an email, use one made just for the quiz or your class, not your personal address.
  • Never put children’s names, photos or contact details in a quiz, in the author, or in a picture.

Several quizzes by the same person? Put them in a folder with a collection.json that holds the author once. See Collections and folder layout and Saying who made it in the README.

5Changing the button and message text

Every button and message has a friendly default, such as “Start the quiz” and “Next question”. To use your own words, add a ui section to your quiz. Change as many or as few as you like:

"ui": {
  "start": "Let's go!",
  "correct": "Spot on!",
  "messages": {
    "great": "Star student!",
    "keep_trying": "Every try makes you better!"
  }
},

The three messages are shown on the end screen: great for 80% or more, good for 50% to 79%, and keep_trying for less than that.

Keep it kind Short, warm words work best, and the same message should suit every child. Please avoid anything that sounds like a telling-off.

The README has the complete list of texts you can change.

6Adding images

Upload a picture

  1. On your computer, make sure the picture is a .png, .jpg, .gif or .webp file under 5 MB, with a simple name such as rocket.png.
  2. In your fork, open the quizzes folder. Click Add file, then Upload files.
  3. Drag the picture onto the page, or click choose your files.
  4. Write a short note, choose Commit directly to the main branch, and click Commit changes.

You can drag a whole folder, such as images, to keep things tidy. Then the picture’s name in your quiz starts with the folder: images/rocket.png.

Use it in a question

Give the picture’s name, and describe it in image_alt. The name is written from the quiz file’s own folder, and capital letters matter.

{
  "text": "What is this called?",
  "image": "rocket.png",
  "image_alt": "A tall white vehicle with fins and a pointed top",
  "options": [
    { "text": "A rocket", "correct": true },
    { "text": "A boat" },
    { "text": "A train" }
  ]
}

An answer can be a picture too: { "image": "rocket.png", "image_alt": "A tall white vehicle with fins" }. When a picture sits next to words that already say everything, use "image_alt": "".

Write good picture descriptions

The description is read aloud to children who cannot see the picture.

  • Say what you see, not the answer. If the question is “What is this?”, do not write the name in the description.
  • For picture answers, describe what makes each one different.
  • One short sentence, without “Picture of”.
  • A test: read the quiz aloud with the pictures hidden. Can someone still answer?
Use pictures you may use Use your own drawings and photos, or pictures with an open licence (such as Creative Commons) and write down where they came from. Never use photos of children. The sample pictures in this project are Noto Emoji by Google (Apache License 2.0).

Linking to a picture on another website (an https:// address) also works, but the other site can then see the IP address of each child who plays. Uploading the picture yourself avoids that. SVG pictures are not allowed as uploads for safety reasons; convert them to PNG. More in Images and Describing images in the README.

7Multiple languages

One quiz can be played in several languages. Children switch with flag buttons and keep their place and score. To turn it on, list the languages in languages, then write every piece of text once per language. The first language is the one it starts in.

languages-quiz.json 
{
  "languages": ["en", "it"],
  "title": { "en": "Space Quiz", "it": "Quiz sullo spazio" },
  "questions": [
    {
      "text": { "en": "Which planet do we live on?", "it": "Su quale pianeta viviamo?" },
      "explanation": { "en": "We live on Earth.", "it": "Viviamo sulla Terra." },
      "options": [
        { "text": { "en": "Earth", "it": "Terra" }, "correct": true },
        { "text": { "en": "Mars", "it": "Marte" } },
        { "text": { "any": "Jupiter", "it": "Giove" } }
      ]
    },
    {
      "text": { "en": "How many planets are there?", "it": "Quanti sono i pianeti?" },
      "options": [
        { "text": { "any": "6" } },
        { "text": { "any": "8" }, "correct": true },
        { "text": { "any": "12" } }
      ]
    }
  ]
}
  • Every text needs every language. A missing translation is reported, so no child ever sees a gap.
  • "any" saves typing. It is the text for every language that has no line of its own. Use it for numbers and names ({ "any": "8" }), or as a default with exceptions ({ "any": "Jupiter", "it": "Giove" }).
  • Do not mix. With languages on, plain text without a language is an error. Without it, texts in language groups are an error.
  • The buttons and messages come in en (English), it (Italian), es (Spanish), fr (French) and de (German).

Details are in Multiple languages in the README.

8When something goes wrong

Each time you save a change, GitHub checks every quiz. If it finds a problem you get a red cross, but your site stays online as it was, because the website only changes when someone rebuilds docs. Nothing is broken for your pupils.

Find out what is wrong

  1. Open the Actions tab. A run with a red cross has failed.
  2. Click the name of that run.
  3. Under Jobs (left side), click the job with the red cross. The step that failed opens by itself.
  4. If it is the step called Validate quizzes/, a quiz has a problem. Read the red lines.
  5. If the message says docs/ is out of date, your quizzes are fine, but the website has not been rebuilt. Follow “Publish it” in Write your first quiz.

Each line says the file, the place inside it, and what to fix:

ERROR   quizzes/space-quiz.json: questions[1].options: exactly one option must have "correct": true (found 0)

questions[1] is the second question (counting starts at 0), so the second question has no right answer. Open the file, fix it, and commit again. A new check starts by itself.

Common error messages and what to do
The message saysWhat to do
not valid JSON at line L, column CA punctuation slip near that spot: a missing or extra comma, quote or bracket. The last item in a list has no comma.
unknown field "corect" (did you mean "correct"?)A field name is misspelt. Use the suggested one.
exactly one option must have "correct": true (found 0 or 2)Mark one right answer per question, no more and no fewer.
needs at least 2 entriesAdd more answers to that question.
questions_per_quiz is 5 but the quiz only has 3 questionsAdd questions, or lower the number, or remove the line.
missing translation "it"Add the Italian text, or use { "any": "..." } if it is the same in every language.
image file not foundThe picture’s name or folder is wrong, or you have not uploaded it yet. Check spelling and capital letters.
local images must be one of: png, jpg, jpeg, gif, webpConvert the picture to PNG or JPG.
image is too large (over 5 MB)Make the picture smaller. A few hundred pixels wide is plenty.
author.url: must be a web addressWrite the full address, starting with https://.

The README lists more in Common errors and fixes.

Other hiccups

  • The page says “404”. In Settings → Pages, check that Source is Deploy from a branch, with branch main and folder /docs (Make your own quiz site in 10 minutes, step 3). Also check that the docs folder in your repository contains a file called index.html.
  • I saved a quiz but my website did not change. That is expected: saving only runs the checks. The website changes after someone rebuilds docs (see “Publish it” in Write your first quiz).
  • The quiz page says there are no quizzes yet. Every quiz file was deleted. Add one as quizzes/your-quiz.json (see Write your first quiz).
  • The build says “quizzes/ folder not found”. The whole quizzes folder was deleted (GitHub removes a folder once it is empty). Create quizzes/your-quiz.json again with Add file.
  • My change is not there yet. After the new docs folder is pushed, wait a few minutes, then refresh. Browsers sometimes keep an old copy for a little while.

9Turning off the project pages

By default your site shows this project’s welcome page and guide, with your quizzes under quizzes/. If you want your own quiz list to be the front page, build without the project pages. This is a job for the build tool (see “Publish it” in Write your first quiz):

  1. In a terminal, in your fork’s folder, run python scripts/build_docs.py --quizzes-only.
  2. Commit and push the changed docs folder to main.

Your quiz list is now at https://<your-username>.github.io/<repository-name>/. To bring the project pages back, run python scripts/build_docs.py without --quizzes-only and commit again. Remember to use the same command every time you rebuild.

10Sharing a quiz without a website

Sometimes you just want one file to email, put on a USB stick, or open without internet. The quizgen program can turn a quiz into one self-contained web page that opens with a double-click.

This needs a terminal and Python on your computer, so ask a colleague, a family member or a developer for help if that is new to you. Then, in a terminal:

pipx install git+https://github.com/rcocetta/school-quiz
quizgen build space-quiz.json

That writes space-quiz.html next to your quiz. Details, other install options and what each command does are in the README: Installation and Output modes.

11Contributing back

Made a quiz other children could enjoy? You can add it to the shared library at rcocetta/school-quiz with a pull request, which is a polite way of saying “please add my change”. A single quiz goes in the quizzes folder. A whole set, such as your class’s or your school’s, goes in its own folder, quizzes/<collection>/, which gets its own page.

Only send your own files A contribution must only add your quiz (or change your own files). If you have deleted the sample quizzes in your fork, a request sent from that fork would try to delete them from the shared library too. Do not send it from such a fork.
  1. Use a fork that still has the sample quizzes untouched. If you only tidied up your fork’s main branch, the simplest way forward is to open an issue, attach your quiz file and ask for help. Someone will add it for you.
  2. In that fork, add your quiz file (Write your first quiz) at the right place, for example quizzes/class-4b/space-quiz.json. Typing a folder name and / in the file name box creates the folder.
  3. When you commit, choose Create a new branch for this commit and start a pull request and click Propose changes.
  4. On the page that opens, check that the base repository is rcocetta/school-quiz. If you are asked, you can also find the request by clicking Compare & pull request in the yellow bar on your fork, or the Pull requests tab, then New pull request, then compare across forks on the original project.
  5. Before sending, click the Files changed tab. You should see only your own file, added. If you see sample quizzes deleted, stop and open an issue instead.
  6. If you can, rebuild the docs folder with python scripts/build_docs.py and include it in your pull request. If you cannot, just say so in your pull request, and the maintainer will rebuild it for you.
  7. Write a title and a few words about the quiz, then click Create pull request.

Not comfortable with any of this? Opening an issue with your quiz file attached is always fine.

The quiz checklist

Before you send it, please check that:

  • It suits the age group it is meant for.
  • You have double-checked every right answer.
  • Pictures are yours or openly licensed, and you have noted the source.
  • It has no personal data about children: no names, photos or contact details.
  • It passes the checks. The pull request shows a green tick when the quizzes validate. A red “docs/ is out of date” only means the docs folder needs rebuilding, which the maintainer can do. (The first time you contribute, the checks may wait until the maintainer allows them to run.)

The full rules are in CONTRIBUTING.md.
